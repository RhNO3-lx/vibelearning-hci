# 分支记忆、掌握证据与知识模块图：三项调研报告

日期：2026-10-10。依据：项目构想、两轮问题回答，以及用户确认的摘要同步规则。

## 1. 结论与选型

**三条线都有可以借鉴的成熟部件，但本轮没有核实到一个能够直接满足全部需求的现成系统。** 建议采用“可追溯事件＋版本化分支摘要＋独立学习者状态投影”，掌握评估保持可替换，知识图从可靠课程结构起步。以下是设计建议，尚未实施或通过用户研究验证。

| 调研问题 | 本轮结果 | 建议 |
|---|---|---|
| DeepTutor 记忆如何适配？ | 有三层记忆、来源校验、消息分支、上下文压缩；既有普通分支排除兄弟历史，整合更新主要按新增 ID，L3 来源较粗 | 借鉴事件与证据回查，新增摘要 revision、分支接收游标、撤回和回答前同步 |
| 掌握程度能否复用现有机制？ | DeepTutor 有证据记录与评估修复；pyBKT 提供可解释概率模型，pyKT 提供模型基准；对话 KT 有作者代码，但存在学科与数据限制 | 首轮以证据台账为基础，使用简单可解释参考分；在适当细粒度技能上比较 BKT。不要将模块分数包装成已校准概率 |
| Jev 能承担什么？ | 有类型化判断和概率分布；官方承认精确数学、间接推理、长无关上下文等局限 | 作为局部证据分类/量规评价候选，和独立参考比较；不直接承担证明正确性或完整掌握建模 |
| 知识节点与关系如何可靠生成？ | 课程标准可提供层级；概念提取和先修关系预测有研究及部分代码，未覆盖可靠群体帮助程度 | 用课程/教材构建模块与可评价目标，自动生成有来源的候选关系；未经验证的数值留空 |

证据详情见 [DeepTutor源码核查](./DeepTutor源码核查.md)、[来源目录](./来源目录.json)、[源码版本与索引](./源码版本与索引.json)和[检索记录](./检索记录.md)。本轮定向调研不构成完整系统综述。

## 2. 分支记忆：保留三层思想，重定义更新单位

DeepTutor 固定在 v1.6.14 的 `6cf793bd868ba5ecbe64722936d4be8fab5a01df`。核查结论来自源码，不以旧论文推断当前软件。关键差异详见独立源码记录。

### 2.1 四种对象分别存储

| 对象 | 作用 | 更新方式 |
|---|---|---|
| 原始交互事件 | 保存对话、附件来源、工具结果和教学/作答时间 | 不直接覆盖旧证据，增加更正、撤回事件 |
| 分支/子树摘要 | 支持导航和其他分支恢复背景 | 根据依赖内容生成新 revision，注明替代与撤回 |
| 学习证据 | 表达谁在何种条件下表现了哪项能力 | 按原始事件与评价维度去重，记录有效性及评价器版本 |
| 学习者状态 | 聚合证据，供教学与规划使用 | 基于有效证据可重算；与摘要文字分开 |

这是一项架构建议：树负责组织交互，能力依据不受“必须是纯树”的限制。一次回答可关联多项能力，但这些维度共享同一来源，不能视作相互独立的多次练习。

### 2.2 建议的同步规则

摘要记录至少包含 `summary_id / revision / source_node_ids / source_revisions / supersedes / changed_at`；分支保存已接收版本、上下文压缩版本及接收事件。

1. 其他分支新增内容、更正或删除时，标记相关摘要及祖先摘要待更新。
2. 切换分支和每次回答前检查版本；将尚未接收的摘要更新追加到该分支上下文，附来源及替代关系。
3. 普通新增可以按预算聚合为较高层摘要，避免父摘要与子摘要重复注入；更正与撤回优先处理。首次分叉可接收其他相关子树的当前摘要，之后只同步变化。
4. 注入事件与接收游标一起提交，幂等键可用 `branch_id + summary_id + revision`。仅“生成了摘要”不等于该分支已经接收。
5. 压缩时重新引用当前有效摘要及状态，不把已撤销判断继续折入压缩摘要；压缩结果保留覆盖版本，原文仍可查询。
6. 若更正尚未处理完成，回答使用当前有效证据与撤回标记，或等待相关投影完成；不可把旧版本当作已同步。异步任务完成后产生新的变更通知。

无需让学习者管理这些游标。可在用户需要核查时显示“此次参考了哪些支线、掌握依据来自哪些作答”。摘要作为普通数据处理，不能提升为系统指令。

DeepTutor 的 snapshot diff 已能检测修改/删除，但其 L2/L3 的新输入选择按已见 ID 做差分；我们的版本同步应借鉴前者，而不是原样移植后者。[固定 update 源码](https://github.com/HKUDS/DeepTutor/blob/6cf793bd868ba5ecbe64722936d4be8fab5a01df/deeptutor/services/memory/consolidator/modes/update.py)

### 2.3 删除和历史记录

删除对话节点与删除知识模块要区别处理：前者撤销从该节点提取的有效证据，并更新相关摘要及画像；后者按已确认语义移除路径关联、保留历史证据，概念身份可留作历史引用并标记删除，不能因重新添加同名节点就自动继承能力。

知识节点从当前目标排除不改变全局能力状态。撤回后重算相关能力及教学建议，保留变化原因。事件回放按真实发生/生效时间进行，不按树的深度遍历；学习者返回旧节点时仍处在当前时间，可以使用已经发生的其他支线信息。

## 3. 掌握证据：哪些成熟机制适合复用

### 3.1 候选比较

| 候选 | 可复用机制与已核实材料 | 对本项目的限制 |
|---|---|---|
| DeepTutor Mastery Path | 讲解不授予掌握；记录提示、来源和尝试；作废题目后重算；自评与系统状态可分开 | 最近正确率是启发式，定性 passed 依赖 tutor 判断；原始文本评分函数不能直接评价证明 |
| [pyBKT](https://github.com/CAHLR/pyBKT) | 开源 BKT 与扩展，提供拟合/预测接口；源码分别输出答对预测和潜在知识状态预测 | 需要技能标注、作答序列及可用参数；广泛模块和开放项目不能无条件压成一个二元技能 |
| [pyKT](https://github.com/pykt-team/pykt-toolkit) | 数据预处理、划分、训练与评价框架 | 是研究基准工具箱，非现成画像服务；深度模型需要数据和训练，隐藏状态也不直接提供可协商证据解释 |
| [Dialogue KT 作者代码](https://github.com/umass-ml4ed/dialogue-kt) | 对话先标注 KC 与正确性，再训练/评价；代码排除不可评价轮次，预测时避免读入目标学生答案 | 数学数据与既定知识标签，不能直接保证本科证明、跨会话项目任务有效 |
| [可协商学习者模型](https://link.springer.com/article/10.1186/s41039-016-0035-3) | 展示依据、质疑证据/推理、补充证据、记录不同判断 | 主要借鉴操作语义；本轮未核实一个可直接安装且完整适配的现代组件 |

pyBKT 原文描述猜测、失误、学习和遗忘等模型参数，并提供可组合扩展；这些参数需要拟合或有依据的设定，不能用 Jev 的置信度替代。[EDM 2021 原文](https://educationaldatamining.org/EDM2021/virtual/static/pdf/EDM21_paper_237.pdf)

对话 KT 的 LAK2025 原文把知识标注、作答评价和追踪分开；其专家评估涉及三名前数学教师、30 段 CoMTA 对话、166 对轮次。作者明确说明缺乏跨对话的学生关联数据、领域局限于数学。其预测结果不等于长期保持或迁移已经改善。[原文 v2，§§3、7、8](https://arxiv.org/html/2409.16490v2)

### 3.2 首轮建议：可替换评价器＋证据投影

建议记录以下证据字段：原始事件 ID、用户 ID、概念/目标 ID 及版本、题目/任务、学生原始回答、提示及答案暴露情况、结果或多维量规评分、评价依据、评价器与量规版本、产生时间、有效/撤回状态。

展示层同时提供：

- 活动尺度：接触过、自评理解、提示下完成、独立完成；
- 能力维度：例如解释、执行/计算、论证或设计、迁移；
- 数值参考及其语义、证据数量和最近时间；
- 无足够证据、评价有争议等状态。

证据为空时显示未知，而不是 0 分。模块状态是子目标覆盖概况，不因一个子目标通过而宣告整个模块掌握。一次问答可以产生“暂时错误假设”，但只有经核查的表现才支持能力判断；一次错误不足以自动升级为稳定的常犯错误。

首轮可借鉴 DeepTutor 的最近正确率作为透明参考分，但应将同题重试、提示练习和独立作答分开，并避免展示“掌握概率”。在具有稳定细粒度技能、可靠标准答案和足够数据的子领域，再用 pyBKT 比较下一次独立作答预测。BKT 的潜在状态与答对概率也应分别呈现。

面对“你低估了我”：保留自评，提出短诊断任务，将新增证据写入并重算；若发现题目/答案错误，作废或更正旧证据后重算，不直接改写一个总分。摘要、画像及推荐均引用同一证据投影，避免相互循环充当证据。

### 3.3 Jev 的具体角色

官方原语包括 Choice、Score、Noul，适合范围清晰的结构化判断。[官方介绍](https://docs.typesafe.ai/introduction) `confidence` 是由概率分布计算的统计量；例如 Choice 的公式为 `(最大概率 - 1/n)/(1 - 1/n)`，不自动表示该判断在本领域的正确率。[置信度文档](https://docs.typesafe.ai/confidence)

截至查阅日，Models 文档列出 `jev-1.13.0`，输入价格为每百万 token 0.042 美元、输出免费；仅支持文本，总请求 64k token，state 加最长问题限制 32k。中文等语言的准确性不及主要训练语言英文。应固定模型版本并保存响应版本；本轮没有付费 API 实测。[Models](https://docs.typesafe.ai/models)

官方局限页说明精确数学、数值、复杂间接推理、无关长输入及选项顺序可能造成问题。这对数理证明场景直接相关。[Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

建议候选用途：从确定的目标集合选择能力标签；判断是否为自评/猜测/独立作答；根据显式量规评价某一局部解释；辅助筛选相关原文。提示使用优先由工具与交互日志确定，不让模型猜测；多个独立判断共享上下文仍可能相关，不能随意相乘概率。

程序行为优先用固定测试/静态检查评价，证明使用教师量规和参考论证，多步复杂判断保留强评价器或人工抽检。Jev 不负责计算 BKT、生成教材、证明全局图正确或直接输出完整画像。官方发布页主要用其他模型平均预测作 workflow 参考，不是本项目的教育金标准。[发布评估](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

### 3.4 如何验证“减少误判”

两层验证分别开展：

1. **局部评价正确性。** 教师独立标注真实或专家构造的作答，包含错误证明、否定句、正确但不同表述、提示后答案、证据不足等。对 Jev、普通 LLM 量规评价、可执行检查比较 macro-F1、错误授予掌握率、拒评覆盖率，以及概率校准/Brier score。中英文与选项顺序分别检查。
2. **状态预测有效性。** 冻结时点前的全局有效证据，预测之后尚未看到的独立任务表现；报告预测校准、误判、自评纠正后的变化和证据覆盖。按学习者拆分验证数据，防止同一回答、同题变体及后续摘要泄漏到训练/评价输入。

潜在掌握没有一个可直接观察的绝对金标准；专家诊断与后续独立任务是不同效度证据，应并列报告。无需 AI 的理解/迁移改善仍是后续假设，不能从导航改善推导。样本量和通过阈值应在试标注后确定，本报告不预先编造万能阈值。

## 4. 知识模块与关系：现成材料、算法和工具

### 4.1 可靠结构优先从课程与教材获得

[CS2023](https://csed.acm.org/final-report/) 的知识模型使用知识领域、知识单元、主题与学习结果，并另有能力框架，可以为编程和工程任务提供起始层级。它是课程指导，不是全球统一的个人学习图，也不提供每条关系的群体帮助系数。

[MIT 18.06SC](https://ocw.mit.edu/courses/18-06sc-linear-algebra-fall-2011/pages/syllabus/) 提供课程单元、讲解、练习与考试材料；其 syllabus 明确说多元微积分是正式选课先修，但学习该科目不需要微积分。因此，行政先修、内容依赖、教学推荐顺序必须区分。

建议 UI 首轮维持模块层级，内部仍有少量可评价目标与来源对应关系。即使不展开细知识点，也需要知道某道题究竟检验模块中的什么能力。首个种子领域可选线性代数的一个目标范围或编程实践的有限任务集；这是建议，不替用户决定最终研究领域。

### 4.3 三类边属性怎样获得依据

| 属性 | 可用依据 | 无依据时 |
|---|---|---|
| 关系类型 | 课程/教材明确说明、专家标注、可核查的内容使用关系 | 标记为候选，不强制作为学习门槛 |
| 关系置信度 | 领域标注上校准的模型概率，或来源/专家支持等级 | 留空或显示支持等级，不能把模型自信或资料数量当正确概率 |
| 帮助程度 | 专家定性建议；或适用人群、任务、测量与不确定性明确的群体学习数据 | 留空/定性，避免自动填小数制造精确感 |

“大多数人的表现”需要实际群体数据。课程顺序、Wikipedia 链接和专家多数意见可提供结构依据，却不等价于先学 A 对学习 B 的收益。观察到先学 A 的人表现较好，也可能来自先验能力和学习投入差异；要声称教学因果收益需要相应研究设计。单个用户的路径经历只更新个人建议，不改写通用群体权重。

关系还应带来源段落、适用课程/任务、生成方法、模型版本和审核状态。对真正 prerequisite 的子图检查自环/环；“有帮助”允许双向关系，不应该将整个图强制为 DAG。多先修的 AND/OR 若没有明确依据，不自动推断为硬门槛。

### 4.4 建议首轮管线

1. 从权威大纲/教材目录导入有限模块，保留版本与出处。
2. 提取模块内的可评价目标，关联习题、示例或项目任务；合并同义词，检查范围重叠。
3. 从明确引用、定义使用及教学说明生成候选关系；章节顺序只作弱信号。
4. 以限定关系模式抽取，附原文依据；运行 ID、来源、自环、硬先修环和重复节点检查。
5. 领域专家核查首轮种子图；学习者仍可以删改目标范围、探索路线，系统记录其个体选择而不覆写来源事实。
6. 从已审核的模块、目标及个人证据产生路线；解释路径建议依据。新增 session 复用现有身份与版本，避免每次重新生成同名节点。

图质量检查包括目标范围覆盖、粒度一致性、来源支持率、关系方向/类型 precision 与 recall，以及路径任务可完成性。评估要抽查候选边、非边和被拒绝边，避免只检查已生成关系高估质量。

## 5. 对首轮研究与技术栈的影响

SQLite 可以表达上述事件、节点、版本、关联与游标，不需要因两张图就先引入图数据库；这是规模受控原型的工程判断。Flask 服务需要独立后台任务队列/执行器处理摘要与评价，并确保回答读取一致版本；本轮不指定具体依赖或开始实现。

2×2 条件应明确关闭的是完整模块：探索树模块包括分叉、树式摘要及恢复机制；知识图模块包括图式目标关联与规划。基础模型、量规评价器、课程材料、可执行检查、知识证据语义和预算原则尽量一致，模块引起的自然行为与记忆差异记录为机制。无树条件可以保留线性摘要和基础记忆，不需要人为取消所有学习支持。

DeepTutor 已有分支和知识相关元数据，因此基线应注明固定版本及具体启用功能，而不是笼统称“无则退化成 DeepTutor”。本项目自研实现也不能未经行为核查就声称与该产品完全等价。测量模块整体效果与证明某个中介的因果作用是两件事，单靠事件日志不完成因果中介识别。

## 6. 调研完成范围与后续决策

本轮完成三项材料调研、三个官方源码仓库 clone 与固定版本核查、DeepTutor 两个纯函数探针、候选机制比较和实现建议。源码探针展示了原始数值策略与文本评分边界；没有跑原项目测试套件、训练 KT/CPL 模型、调用 Jev 或验证真实学习收益。

尚需在实施前选定：首轮领域与教材、评价目标/量规、种子图审核方式、显示参考分的语义。已有确认的分支共享与摘要同步规则不需要重新询问。

建议下一阶段先将这些结果转化为有限领域的设计规格和界面原型，再以独立标注验证评价器及知识图，最后开展模块比较研究。独立掌控系统的诉求可以保留，同时复用经过核查的机制与工具，避免让外部模型成为无法替换的判断来源。
