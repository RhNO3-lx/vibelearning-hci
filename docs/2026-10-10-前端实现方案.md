# 前端实现方案

日期：2026-10-10。授权范围：按照项目构想完成前端，后端另阶段实施。

## 目标和边界

在 code/frontend 下创建 React + TypeScript + Vite 应用，使用 React Flow 实现可操作的交互轨迹和全局知识图。默认中文，桌面三栏，窄屏自适应。以对话为主、图按需展开，保留浮动/吸附及两图并看。

前端以明确标记的演示适配器提供回答、诊断和项目活动，支持本地持久化交互；不调用付费模型，不执行本地命令、不读取用户未选择的文件。知识库上传仅登记文件，模型、子 Agent、技能和工作区的设置留作后端接口配置。密钥不写入 localStorage。用户文件原始内容和图片预览只保留在当前运行期。

## 实现内容

1. 对话工作台：上下文估算、会话工作区、知识库/子 Agent/技能选择、图片粘贴/附件输入、Markdown/数学渲染、划词分叉、普通分叉和主线标记；答题卡、闪卡与项目实践卡。
2. 交互轨迹图：一轮问答一个节点、祖先路径阅读、分叉/添加/删除子树、切换位置、主线、活动类型与知识关联。跨分支信息共享由演示摘要记录表达，保留摘要版本与接收游标；不声称实现生产记忆推断。
3. 知识图：全局模块、展开知识点、能力参考分/证据不足、难点/概要/难度/来源、两图交叉高亮、从当前对话发起诊断分支、路线增删排序及移除原因。关系区分类型、置信度和帮助程度；未知值不编造数值。
4. 配置页面：会话、设置、知识库、子 Agent、技能；新会话目标引导；资源配置与工作台关联。
5. 状态管理：版本化本地存储与损坏回退；稳定 ID；全局删除模块保留历史记录，删除对话撤回其演示评估；只保留一个主线。前端与演示回复适配器分开，便于 Flask 接入。
6. 质量与交付：构建/类型检查、关键状态不变量测试、浏览器实际操作与视觉检查；保存使用说明和功能覆盖清单，中文阶段提交，仅包含本轮文件。

## 设计取舍

- 以暖白、深青绿和低饱和薄荷色构成安静的学习空间，强调当前任务而非密集管理面板。
- React Flow 提供拖动、缩放、节点/边选择；知识点展开不改变模块身份。
- 对话默认显示选定节点的祖先路径；其他分支摘要以更新记录补充，符合已确认的共享语义。
- 不重新询问已确认规则；视觉、组件和工程细节按可逆原型处理。教学评价效果、可靠自动建图与沙盒执行不属于本轮完成声明。
