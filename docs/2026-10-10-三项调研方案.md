# 三项调研方案

日期：2026-10-10。范围：调研与设计建议，不开始产品实现。

## 已确认的设计前提

- 探索树组织共享信息，不隔离分支；各分支维护自己的上下文。
- 切换分支及每次回答前检查摘要版本，追加尚未接收的更正；新版本明确替代旧版本，删除产生撤回事件。
- 掌握判断基于可追溯、去重的原始证据；学习者模型全局共享。
- 知识关系分别记录类型、置信度、帮助程度；个人状态与通用知识结构分开。
- 默认仅从当前目标排除模块；全局删除移除路径关联并保留历史证据。
- 研究探索树与知识图模块整体影响；首轮关注导航与学习状态判断准确性。

## 工作方法与交付

1. 固定 DeepTutor 官方仓库 commit，沿事件写入、记忆整合、上下文注入、分支恢复和删除链条检查源码与相关测试。区分 README 主张、源码机制与运行验证；提出适配清单。
2. 查阅知识追踪、开放学习者模型及开源实现，比较证据采集、作答评价、状态更新和纠正撤回。核查 Jev 官方接口与置信度语义，提出独立验证方式。
3. 查阅概念划分、先修关系识别、教材/课程来源及可复用工具，区分领域结构、群体统计证据与个人帮助程度；提出首轮可行管线和质量标准。
4. 报告保存至 research/learning-memory-knowledge-2026-10-10/，包含调研报告、来源目录、源码核查记录及检索记录。引用固定版本或原始来源，标明未验证部分。
5. 检查报告与引用、归档本轮新增文件；阶段性提交仅包含本轮产物，保留已有未提交改动。

## 证据边界

本轮为定向调研，不声称系统综述或教育效果已证实。源码核查不等于部署运行；通用概率输出不等于学习者掌握概率；先修关系分类置信度不等于关系强度。无需 API key 或用户数据即可完成材料核查，付费服务实测后置。
